## Format de Versioning

### Version Format: MAJOR.MINOR.PATCH

- **MAJOR** : Changements incompatibles de l'API (breaking changes)
- **MINOR** : Ajout de fonctionnalités (rétro-compatible)
- **PATCH** : Corrections de bugs (rétro-compatible)

### Exemples

- `1.0.0` → `2.0.0` : Breaking change
- `1.0.0` → `1.1.0` : Nouvelle fonctionnalité
- `1.0.0` → `1.0.1` : Correction de bug
